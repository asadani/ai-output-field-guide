DITA

Author reusable documentation topics and assemble them for different publications.

Advanced · 3 drills · Reviewed 2026-10-24

See an examplePractise

What it helps you do

Manage documentation whose reusable information must appear consistently in several products, guides, or delivery formats.

Starting knowledge: Some familiarity with structured documentation and XML helps.

  • Write a topic around a bounded reader need.
  • Use maps to assemble topics into a publication.
  • Use controlled reuse and specialization deliberately, with ownership for shared material.

The problem it came from

DITA originated at IBM and became an OASIS standard in 2005. Its name is Darwin Information Typing Architecture.

The OASIS 1.3 overview explains topic-based authoring, maps, specialization, and reuse. This entry uses that edition as its reference rather than claiming it is the latest edition.

Work through an example

STARTING POINT
Three event handbooks copy the same cancellation instructions. An update reaches only two of them.
APPLYING THE APPROACH
Topic: cancel-registration
  Purpose: cancel an existing workshop registration.
  Prerequisite: a confirmed registration.
  Steps: open booking; choose cancel; confirm.
Map A: participant guide → cancel-registration
Map B: organizer help → cancel-registration
  • This is a conceptual sketch, not DITA XML.
  • Reuse has a named source instead of several untracked copies.
  • Publication context still needs review: shared steps may have different prerequisites.

Where it helps. Where it stops.

Use it when

  • A help collection repeats the same task across product editions.
  • Several manuals must share reviewed warnings and reference material.

Potential benefits

  • A shared topic can reduce contradictory copies.
  • Separating content from assembly supports several publication structures.

Limits and common mistakes

  • Adopting XML without a content model does not produce useful reuse.
  • Tooling, specialization, and shared ownership can cost more than they save for a small one-off article.

DRILL 03 Not attempted

Two manuals share setup steps but use different warnings. How would you structure the reuse?

Hint

Reuse is a design choice, not a word-count target.

Explained answer & self-review rubric

Reuse the genuinely common setup material. Keep product-specific warnings attached to their correct contexts and review each assembled manual. Do not force incompatible instructions into a universal topic.

  • Identify genuinely shared content
  • Keep context-specific constraints
  • Review assembled outputs
