Architecture & structure · Modeling language

UML

Choose a defined notation for structure, interactions, activities, or state changes.

Intermediate · 3 drills · Reviewed 2026-10-24

See an examplePractise

What it helps you do

Make the aspect being modeled explicit so readers can inspect relationships or behavior with a shared notation.

Starting knowledge: Understand the entities or behavior you want to model; notation can then be introduced.

  • Use a class view for types, associations, and multiplicities.
  • Use a sequence view for messages in time order; include important alternate paths.
  • Use activity or state-machine views for flow or lifecycle questions.

The problem it came from

UML unified earlier object-oriented modeling approaches and became an OMG standard in 1997. The OMG specification is the authoritative reference for its semantics.

This entry references UML 2.5.1. A class diagram, sequence diagram, activity diagram, and state machine describe different aspects of a system; they are not interchangeable decorations.

Work through an example

STARTING POINT
The system checks access and returns a document.
APPLYING THE APPROACH
Sequence sketch:
Reader → App: read document
App → Authorization: check membership
[allow] App → Store: retrieve
[deny] App → Reader: denied

Class sketch: Team 1 — 0..* Membership
Activity sketch: request → check → allow / deny
State sketch: Membership active → revoked
  • These textual sketches introduce distinct UML views; they are not a full normative model.
  • The deny branch is observable.
  • The class relationship and lifecycle need their own domain review.

Four views, four questions

Original teaching diagrams. Their simplified scope is explained beneath each view.

Sequence view

The reader requests a document. The application checks authorization. Allow leads to a store read; deny leads to an access-denied response.

Class view

One Team relates to zero or more Membership instances. Each Membership relates to exactly one Team. This example does not define the member’s identity or role policy.

Activity view

Start, check access, then branch. Allow retrieves a document; deny returns an error. These paths end without granting access on the denial path.

State view

An active membership transitions to revoked on a revocation event. The diagram does not define reinstatement or the treatment of in-flight requests.

Where it helps. Where it stops.

Use it when

  • You need to examine object relationships or an interaction.
  • The question concerns which event changes an object’s state.

Potential benefits

  • A suitable diagram can expose missing participants or outcomes.
  • Defined notation supports discussion beyond an author’s private drawing conventions.

Limits and common mistakes

  • A diagram is only as accurate as the model it depicts.
  • Notation tools may implement a subset or simplified semantics; rendered output is not a conformance check.
