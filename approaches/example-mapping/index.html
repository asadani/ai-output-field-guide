Example Mapping

Explore a feature by separating rules, concrete examples, unanswered questions, and scope.

Introductory · 3 drills · Reviewed 2026-10-24

See an examplePractise

What it helps you do

Find important decisions before a requirement is mistaken for shared understanding.

Starting knowledge: No specialist knowledge is required.

  • Start with one bounded story.
  • For each rule, try concrete examples including a boundary or failure case.
  • Keep unanswered questions visible instead of silently choosing an outcome.

The problem it came from

Matt Wynne introduced Example Mapping in a 2015 Cucumber article. The practice uses a simple visual arrangement to structure conversations about a story.

The original colored cards distinguish the story, rules, examples, and questions. A digital equivalent can preserve those roles without requiring particular colors or software.

Work through an example

STARTING POINT
Story: let participants cancel workshop registrations. Everyone agrees this sounds simple.
APPLYING THE APPROACH
Rule: canceling a confirmed registration releases one place.
Example: cancel once → release one place.
Example: submit the same cancellation again → release no extra place.
Question: does cancellation trigger an offer to the waitlist?
Out of scope: changing to another workshop.
  • The repeat request surfaces a hidden resource rule.
  • The waitlist action remains unresolved.
  • Moving a related feature out of scope prevents accidental implementation.

Where it helps. Where it stops.

Use it when

  • Refining a feature with product, engineering, and domain participants.
  • A short requirement sounds clear until someone proposes an exception.

Potential benefits

  • Concrete cases reveal missing decisions early.
  • Separating questions from rules avoids presenting guesses as approved policy.

Limits and common mistakes

  • A well-organized board does not create stakeholder agreement.
  • An example set can remain incomplete; deliberately look for conflicting and boundary cases.

DRILL 03 Not attempted

Map a workshop waitlist question into one rule, example, and open question.

Hint

Do not invent a timeout to fill the gap.

Explained answer & self-review rubric

Rule: a full workshop puts a valid new registration on the waitlist. Example: with zero places, a new valid registration is waitlisted and consumes no place. Question: how long does an offer remain valid after a place opens?

  • Separate the rule and case
  • Include resource effects
  • Keep the unapproved duration open
